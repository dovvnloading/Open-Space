# Conditional production design — pre-flux code review required

This proposed conditional standard-release test uses all three metadata-associated positions. It tests whether both final sessions exceed each source's own development constant baseline by 3 declared model-sigma units; the two radio-known cases are positive controls. It does not claim a TDE origin, physical variability, survey population limit, or a globally calibrated p-value. Selection, grouping and target/control pools are in proposed-packet.json and control-metadata.csv. Neither phase has been executed on real flux; development baselines, selected stable IDs, scales and covariances must be frozen after authorized development and before any holdout analysis.

`read_development.py` hashes the two archive products, filters source/image metadata to the frozen development IDs using Parquet predicates, and validates the resulting source/image sets before conversion or return. Parquet may physically decode full compressed column chunks containing holdout rows; the code does not promise that the bytes were not decoded. No actual call has been made. It does not implement holdout access. All returned rows must pass phase and duplicate guards; all rejected rows retain reasons.

`conditional_pipeline.py` keeps signed source peak flux including forced fits, requires finite peak flux/error, positive uncertainty and local RMS, positive image restoring-beam axes, and rejects flagged bad fits or sibling detections; non-forced rows with missing fit flags fail. Forced rows may have undefined fit-specific flags but never a true flag. Released source-catalog filters already impose their selection function. No absolute S/N cut is applied to target forced flux. The 20-control minimum, four development sessions, control S/N >=5, fractional MAD <=0.10, gain uncertainty floor 0.03, and both-session threshold 3 are proposed fixed values pending review, not tuned to actual source data.

Control IDs come only from the fixed metadata pool. A control qualifies solely on development data, with >=4 distinct sessions and detection S/N >=5 and median-based fractional MAD <=0.10. Per-image gain is the median ratio to these development-only control baselines, requiring >=20 frozen controls on every used image; no gain is rescued using a new control in holdout. Session combination takes the mean of images and retains the largest single-image formal error and gain uncertainty as fully correlated, never gaining sqrt(n) from a 15-minute pair. The weighted constant baseline is variance-inflated by max(1,chi2/dof). The same baseline variance is shared by both subsequent comparisons. These assumptions do not account for all cross-session calibration/selection correlations, intrinsic control variability, neighboring source leakage or false positive tails; any output is conditional on them. Missing/failed sessions or inadequate controls stop analysis, not substitution or extrapolation.

The prospective 3-source question produces three conditional flags; no highest-flux selection. For each source both heldout z values must reach 3, with the frozen shared baseline variance included in each marginal. Under calibrated Gaussian marginal errors, union bounding three prespecified candidate tests gives a conditional upper bound 3×0.00135=0.00405 regardless of cross-epoch correlation; it is not a measured p-value and Gaussian calibration is unverified. Do not use this bound as physical significance.

Run `python results/vast-tde-expanded/test_conditional.py` for synthetic invalid-row, forced signed-flux, duplicate/phase, same-session and null/injection checks; `packet_guard.py` verifies metadata identities. The independent Gaussian test is not a real-background injection test. After explicit development authorization, evaluate controls, coverage, forced-row schema and repeatability; recheck results against real-background perturbations before holdout review. Holdout access needs an independently hashed frozen development output and separate explicit authorization, and is not implemented by the reader here. The code has not been applied to actual data.

Metadata-only feasibility check found at least 67 preselected controls sharing every relevant image for AT2020nov, at least 169 for AT2018hyz, and 200 for ASASSN-15oi, before any development quality or stability cuts. This does not guarantee 20 controls will pass. The frozen development record API writes exclusively and binds reviewed packet and code SHA-256 values; its digest must be independently reviewed and supplied for any later holdout orchestration. Shared calibration between different sessions and uncertainty from data-dependent stability selection are not calibrated by the variance formula. No general holdout archive reader is supplied.

Gain median standard error uses `1.2533 × 1.4826 × MAD / sqrt(n)` before the provisional 3% floor. Cross-session calibration covariance, control-selection uncertainty, image blending and the 3% floor are not empirically calibrated; resulting z values are conditional model diagnostics, not calibrated significance.
