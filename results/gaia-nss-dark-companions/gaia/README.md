# Gaia mass and orbit screen

The DR3 two-body file yields 983 unique sources above the 1.4-solar-mass point-estimate screen, including 112 above 3. Each entry remains conditional on its orbital solution and light model. In the 3-solar-mass stratum, 55 solutions use a published IsocLum primary mass and 57 qualify from the mass function alone. One source has two independent solutions in the larger stratum. Read decimal Gaia identifiers as strings or 64-bit integers.

```sh
python screen.py --cache /path/to/cache
python diagnostics.py --cache /path/to/tap-cache
```

The input and output counts by solution type, direct URLs, byte counts, publisher MD5 checks and calculated SHA-256 hashes are in [depth.json](depth.json). [mass_screen.csv](mass_screen.csv) preserves every orbit that passes. [source_diagnostics.csv](source_diagnostics.csv) has one row per source with position and proper motion, RUWE, visibility periods, image-parameter-determination diagnostics, Gaia RV amplitude, variability statistics, variability classification, and selected astrophysical parameters. [diagnostic_inputs.json](diagnostic_inputs.json) records hashes and counts for each ordered ESA TAP batch.

For SB1 and circular SB1 solutions the calculation uses the single-lined RV mass function, `f = K^3 P (1-e²)^(3/2)/(2πG)`. The edge-on mass solves `M2³/(M1+M2)²=f`. For astrometric solutions we derive the photocentre semimajor axis from the larger singular value of the Thiele–Innes matrix and evaluate `f_phot=(a0/parallax)³/P_yr²`. The astrometric mass is a dark-photocentre estimate. If companion light matters the dynamics require a separate light-ratio model. For combined AstroSpectroSB1 solutions the additional RV column uses C and H, in AU, through `(C²+H²)^(3/2)/P_yr²`. Orbits from the alternative and targeted astrometric pipelines are retained with their solution types. The primary-mass join matches binary_masses combination methods to solution type. The Gaia documentation describes IsocLum as an isochrone-based estimate for main-sequence stars. Stellar evolution, composite light and astrometric errors can invalidate an individual mass estimate. When no applicable IsocLum mass is available the screening calculation uses M1=0 as a conservative floor within its dynamical model.

The sample has 345,265 distinct source IDs with finite, positive mass function and 188,638 distinct sources with an applicable IsocLum estimate. For stars missing the latter, the low-mass floor has less sensitivity. Eclipsing and SB2 rows provide classification flags, never an unseen-companion mass estimate in this stage. No signal-to-noise, scan-period or astrometric-quality cut is hidden in the source counts. The ±3% windows near 62.97 days and one year flag a diagnostic, with the annual window a heuristic. The four ESA-retracted astrometric entries are specifically flagged. High single-star RUWE is expected for some genuine astrometric binaries. A low value, the absence of Gaia variability labels, or a good formal orbit fit does not establish darkness. DR3 RV summary points have no orbital phases and receive no independent RV weight.

Data products and methods reference the [Gaia DR3 NSS data model](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_datamodel/sec_dm_non--single_stars_tables/ssec_dm_nss_two_body_orbit.html), [Gaia Collaboration 2023, A&A 674 A34](https://doi.org/10.1051/0004-6361/202243782), [Gaia DR3 known issues](https://www.cosmos.esa.int/web/gaia/dr3-known-issues) and [Damerdji et al., A&A 693 A124](https://doi.org/10.1051/0004-6361/202450600).
