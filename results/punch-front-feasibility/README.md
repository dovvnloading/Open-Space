# PUNCH front feasibility: metadata phase only

Question: can an outward-moving white-light front selected from disjoint early observations predict its location in a later, previously unread exposure? The observing unit is a front, not a pixel or a mosaic tile. A failure to find the predicted front, given valid coverage and a predeclared noise/registration tolerance, falsifies that particular propagation prediction; it does not prove the absence of a CME. Brightness is line-of-sight scattering, not a direct density measurement. Stationary starfield, detector-frame structure, seams, changing background and projection are alternatives.

Three 2026-11-01 v0l CTM mosaic products at 00:00, 00:08 and 00:16 are frozen access proofs, not an event-selected sample. Their actual FILE PROVENANCE tables list the nine distinct CR1/CR2/CR3 level-1 parent files; independently queried parent headers establish 24-second exposures and nonoverlap across epochs. See provenance.json, parent_headers.json and receipts.json. Mosaic windows and parent identities do not prove independent systematic errors. Four-spacecraft TELESCOP header is generic: v0l excludes NFI. Exact byte-range hashes are receipts, not full-file hashes. No science pixels were decoded. Range responses can contain bytes beyond the FITS header; none were interpreted.

Preliminary design: reserve 00:00 and 00:08 for development and 00:16 for a prospective prediction, with later epoch unopened until an explicit separate authorization. Prior to any image access, a reviewed executable protocol must fix detector-specific ROI, celestial and instrument-frame masks, geometric mapping, background model and its independent inputs, valid footprint/quality coverage, allowed speeds, sign, tolerances, search trials and controls. A known CME (e.g. 2025-05-31) is an external positive calibration, not proof this November interval contains a front. Build synthetic moving-front and detector-fixed/star-fixed injection and registration controls. Parent overlap, shared preprocessing backgrounds, missing independent comparison, incomplete masks or inadequate coverage make the experiment inconclusive. One 8-minute separation and three epochs may be inadequate: do not tune or backfill after image inspection. L3 is excluded until exact parent and background windows are shown disjoint.

No fixed ROI or scientific threshold is yet defensible from these metadata. Therefore this is NOT a ready-to-execute scientific protocol or authorization for image access. guard.py only checks the selected metadata identities and temporal separation and refuses all science phases. This is an explicitly staged planning record. Version-specific WFI photometry, registration, masks, L1/L2 background lineage, actual ROI coverage and independently covered coronagraph geometry still require proof. SOHO/LASCO is a potential comparator; neither coverage nor geometry for this interval is established. Catalog/event history for any eventual candidate must be recorded before a novelty assessment.

Primary references: [mission data overview](https://punchbowl.readthedocs.io/en/latest/data/data_overview.html), [data versions](https://punchbowl.readthedocs.io/en/latest/data/data_versions.html), [version-specific NFI exclusion](https://punch.space.swri.edu/punch_news.php?story=2026-09-18_punch_news_a-year-of-nfi), [existing PUNCH CME tracking](https://science.nasa.gov/science-research/heliophysics/nasas-punch-sharpens-solar-storm-forecasting-in-first-test/). NASA already reports a May 31, 2025 CME tracking example, so propagation tracking itself is not a novel result.
