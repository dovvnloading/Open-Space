# Bright catalog receipt discrepancy

The deposited `bright.tsv` is 26,888 bytes and has SHA-256 `b31187bff9d66fd2cae40aee0d27c4fb32056ae96bc40fb40e6eb93b227123b5`, matching the original HTTP response receipt in `ffi_archive_receipts.json`. It parses to 157 distinct Gaia EDR3 IDs. All 157 rows of `extension_parent.csv` match those IDs and all 12 retained parent catalog fields (1,884 comparisons, numeric values compared numerically). This checks the deposited parent table, not the unavailable response below.

At commit `517ecc60756cd63e9563ff4159f9077890482f49`, the catalog, HTTP receipt and `catalog_body_sha256.json` were deposited together. The latter originally attributed SHA-256 `91f3ca733b13ed6556754c744fdf14e523127f16514c7c8c99fab0390125729f` to `bright.tsv`. Its corresponding bytes and size have not been identified; neither LF nor CRLF conversion of the deposited bytes produces that digest. The active manifest now identifies the deposited bytes and agrees with the separately recorded HTTP receipt. The original digest is retained here, without asserting that its unavailable bytes had the same rows or were used in an earlier calculation. The deposited catalog, original HTTP receipt, and scientific outputs have not been changed.
