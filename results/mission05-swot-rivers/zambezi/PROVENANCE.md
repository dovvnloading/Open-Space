# SWOT sources and matchup methods

The two windows are anchored at historical hydrometric station coordinates, Chavuma (22.68° E, 13.08° S, rounded) and Nana’s Farm (25.65139° E, 17.82028° S). For each station, the acquisition script selected the six nearest type-1 river reaches among the 271 records returned by the PO.DAAC Feature Translation Service's Zambezi name search. Distance is from gauge coordinate to nearest SWORD polyline vertex in a local equirectangular metric. This selection can miss an unnamed branch. It intentionally excludes falls, lakes, and unreliable topology types. The Zambezi at Chavuma and above Victoria Falls has a gauged reference at each site. These two targeted windows do not constitute a global scan. The Nana’s Farm coordinate is upstream of the waterfall. The SWORD `dist_out` values suggest about 930 km of intervening river between the two station reaches, allowing for v16 topology uncertainty.

The frozen source CSVs contain every returned reach row, including fill values, sparse algorithm results, bad flags, and missing `time_str`. Each CSV is the exact decoded CSV payload from its Hydrocron JSON envelope. `manifest.json` preserves the complete queries and SHA-256 of each payload and envelope. The envelope carries server elapsed time, so repeated retrievals can give different envelope hashes with identical measurements. Match each row to its Level 2 ZIP with `granuleUR`. Original units, repeat cycle, pass, CRID, SWORD version and `range_start_time` are retained. The gauge-station distance uses the static prior river geometry rather than the centroid of the measured water pixels. [SWORD v16, DOI 10.5281/zenodo.10013982](https://doi.org/10.5281/zenodo.10013982) · [Feature Translation Service](https://podaac.github.io/feature-translation-service/rivers/)

NASA's `SWOT_L4_HR_DAWG_SOS_DISCHARGE_V3` collection is C3905028734-POCLOUD. The CMR result for the Africa continent is explicitly labelled `af_sword_v16_SOS_results_unconstrained_20230502T204408_20250502T204408_20251219T163700`, granule G3927135650-POCLOUD. CMR reports coverage from 2023-03-30T20:20:53Z through 2025-05-02T21:56:59Z and a size of 4,444,985,772 bytes. The actual download used NASA’s public reach-subset service with the collection set to `SWOT_L2_HR_RiverSP_2.0`, enabling Level 4 `sos_*` discharge and matching version-2.0 Level 2 WSE, width and slope. Hydrocron matches the closest SoS timestamp to the observation range start within a tolerance. `time_str` is the actual observation time, while an L2 granule’s range start can occur many minutes earlier. `granuleUR` is the L2 upstream granule, whereas `af_cmr_granule.json` documents the continental L4 provenance. The product exposes algorithm outputs with missing values `-999999999999.0`. `sos_consensus_q` gives the consensus, `sos_sic4dvar_q` a constituent estimate, and no model output was substituted when consensus was missing. Hydrocron does not serve all variables in the L4 netCDF, including its entire uncertainty and prediagnostic information. [L4 DOI](https://doi.org/10.5067/SWOT-SOS-RD3) · [Africa granule](https://cmr.earthdata.nasa.gov/search/concepts/G3927135650-POCLOUD.umm_json) · [L2 DOI](https://doi.org/10.5067/SWOT-RIVERSP-2.0) · [Hydrocron discharge guide](https://podaac.github.io/hydrocron/user-guide/discharge/)

The unconstrained run does not directly assimilate ZRA’s contemporary gauge data. Published v3 work identifies the δHBV2 and GRADES-hydroDL hydrologic-model priors. The published model training windows end in 2000 and 2020 respectively, before the 2023–2025 field dates evaluated here. Historical calibration on overlapping regions remains possible. The L4 algorithms share the input geometry and priors. Therefore algorithm agreement is an internal consistency check. [Confluence system and gauge input routing](https://doi.org/10.1016/j.envsoft.2026.106916) · [Version-3 prior description](https://doi.org/10.1029/2026GL122871) · [δHBV2 training](https://doi.org/10.1038/s41467-025-64367-1) · [GRADES-hydroDL training](https://doi.org/10.1029/2024WR039764)

`coverage.py` defines the primary geometry gate. It requires a valid time and WSE, positive width, reach quality 0–1, no partial-coverage flag, at least 80% nodes observed, crossover quality 0–1, 0 < WSE uncertainty ≤ 0.25 m, and 0 < width uncertainty ≤ 25% of measured width. These study thresholds are analytical decisions. Additional columns give quality-0-only and quality-0–2 sensitivity. A reported slope is resolved at 2 nominal standard uncertainties when `abs(slope) > 2*slope_u > 0`. Both positive and negative slopes can pass this rule. Quality-1 indicates suspect data. The nominal uncertainties and quality flags can miss systematic errors. All 12 reaches lack quality-0 observations. Reach-pass counts are descriptive because neighbors often share the same swath, cycle and processing. [RiverSP product description, Table 11](https://archive.podaac.earthdata.nasa.gov/podaac-ops-cumulus-docs/web-misc/swot_mission_docs/pdd/D-56413_SWOT_Product_Description_L2_HR_RiverSP_20231026_RevBcite.pdf)

`matchup.py` uses only the spatially nearest type-1 reach per gauge and first compares the published station value to an instantaneous pass on the same civil day in UTC+02. Time of gauge reading or averaging window is unknown. The satellite and field discharge represent different spatial supports, and rating-curve uncertainties are unavailable. At ±1 and ±3 days it selects the nearest published day for each satellite record, breaking equal-distance ties toward the earlier gauge day. It keeps the nearest pass per gauge day and algorithm, resolving further ties toward the earlier pass. Missing gauge days or missing algorithms contribute no result. `gauge_match_candidates.csv` retains every potential nearest match within three days, and `gauge_match_summary.csv` tabulates exact dates and both sensitivity windows. The reported correlation is a descriptive Pearson coefficient without an independent-observations significance test. Median signed error is the median of `estimated − station`; median ratio is the median of individual `estimated / station` ratios. No gauge observations were used to rescale the satellite discharge.

`reprocessing.py` compares the two station footprints within the same cycles and passes across v2.0 and D, holding the L4 run fixed. The official v17b-to-v16 SWORD translation assigns Chavuma v16 12297000161 → v17b 12297000161 and Nana’s Farm v16 12279000221 → v17b 12279000181. The translation table rows and source member checksum are in `vD_manifest.json`. The D release includes two deliveries for Chavuma cycle 016 pass 305 with identical observed time and CRID. The higher granule revision (02) is selected for analysis, and both original rows remain in the D payload. Rows from distinct releases remain separate. The diagnostic reports exact same-pass pairs that meet the primary gate in v2.0 alone or in both releases. [Translation file DOI](https://doi.org/10.5281/zenodo.22259077) · [Hydrocron SWORD changes](https://podaac.github.io/hydrocron/user-guide/sword-versions/)

`node_check.py` examines node sequence numbers 5, 20, 36, 52 and 68 across the Chavuma reach on 2025-04-14 (pass 208) and 2025-04-18 (pass 305). The official translation confirms the same node ID in both SWORD versions with zero shift and boundary flags for all five nodes (`nodes/translation_subset.json`). The v2.0 and D prior elevations also match. On April 18 the three sequence numbers 20, 36 and 52 have good v2.0 and suspect D node quality, D-minus-v2.0 WSE differences of 20.10–21.14 m, and observed node coordinates displaced 266–547 m. Three April 14 pairs with finite data in both releases moved 2–21 m and changed in WSE by 0.012–0.047 m, although both versions flagged those three as degraded. The unavailable values are preserved. The node comparison is a diagnostic from the same instrument and processing family, and cannot by itself identify the correct absolute elevation or explain which processing operation produced the shift. L2 D and v2.0 summaries both admit the Apr 18 reach despite the large cross-release disagreement. [NASA RiverSP documentation](https://podaac.github.io/hydrocron/user-guide/versioning/)
