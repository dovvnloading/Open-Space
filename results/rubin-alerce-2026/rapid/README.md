# Screening blue stars for minutes-scale variability

There is one tentative 5.35-minute signal in a blue source near the Euclid Deep Field South. On the February 18 UTC Rubin sequence, Gaia DR3 4830606754977252992 (Rubin object 313761042359910519, ICRS 61.057494°, −49.129764°) gave best single-band periods of 5.37 minutes in *g* (21 observations, semi-amplitude 685 nJy) and 5.36 minutes in *r* (18 observations, 1,195 nJy). Improvement over a weighted linear trend was Δχ² of 191 and 299 using a 0.5% empirical error floor. These are exploratory best fits from the same night. The independent periods across the other four well-sampled nights scatter. A strong coherent period or a physical classification is unestablished.

The TAP query matched 377 Rubin alert objects with a Gaia DR3 counterpart within 0.8″, G > 16, BP−RP < 0.25, ≥10 broker detections and ≥30 forced measurements. This was an alert-selected sample with substantial special high-cadence coverage in February. The 1,500-object query ceiling was not reached. Individual measurements were restricted to 2026 beginning MJD 61041, through the snapshot on November 16. Nineteen ID batches yielded 118,468 distinct measurements, one per object and visit. Of the 377 objects, 215 had at least one eligible single-band run. The search evaluated 1,397 object/night/band series on eight observing nights. It used the visit-image forced science flux and its uncertainty in nJy. No alert-detection significance cut was applied to individual visits. [Rubin observing update](https://www.rubin.community/t/2026-02-27-early-operations-update/11657) · [Prompt Products fields](https://sdm-schemas.lsst.io/ppdb.html)

Within each band/night the search fits sinusoids with a floating intercept and trend, spanning 4–60 minutes with at least two cycles in the observation span. Windows need ≥16 measurements, ≥14 minutes and no single gap exceeding 60% of the span. A median-based eight-scale clip removes isolated excursions. See the code for the sampling grid and the exact error floor. These measurements are on the observatory clock during each short run. For comparison, the longer-baseline exploratory periodograms used barycentric time; they did not deliver a reproducible unique ephemeris. Data from surveys or tables sharing the same photons are not independent validation.

A local correction from other objects on the same detector and visit (at least four valid peers, each normalized by its own night/band median) preserved the first-night signal in direct science photometry. The same-pixel difference-flux product was substantially less convincing. Catalog checks found a faint blue Gaia source with parallax 2.62 ± 1.14 mas. The independent NSC archive adds sparse historical photometry; it does not resolve this proposed oscillation. Among other alerts, the known white dwarf GALEX J122623.5+070109 showed inconsistent periods and common visit-dependent systematics. A third object had already been published as a Rubin SX Phoenicis variable. Neither is claimed as a discovery. [Catalog checks](../catalogs/README.md)

The data folder contains the frozen source selection, fitted peaks for the full screen, individual follow-up measurements, a matched-control summary and the literal TAP query, row count and response digest for each request. The broker copies the LSST `midpointMjdTai` field into `mjd`. Time bins are floor(MJD − 0.5). The matching catalog and broker ingest can evolve. [ALeRCE ingestion transform](https://github.com/alercebroker/pipeline/blob/3461b0937495c2ff4ec6b3a3f069e9227a0b079a/ingestion_step/ingestion_step/lsst/transforms.py)

Run from this directory with Python, NumPy and pandas.

    python search.py data/followup.csv.gz --out followup-peaks.csv
    python retrieve.py /tmp/rubin-rapid-replay
    python search.py /tmp/rubin-rapid-replay/phot*.csv --out all-peaks.csv

The first command is offline. The remaining commands replay all queries and recompute the screen with live broker data. The peak file in the repository records the original results. The compact sample cannot support an occurrence estimate.
