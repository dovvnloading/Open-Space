# Independent catalogue refits

The bulk pass attempts a separate Find_Orb fit for each distinct JPL identifier in the frozen `e ≥ 1` query. A fit can fail or admit many orbits consistent with its observations. The bulk pass supplies a numerical screening result. The [individual astrometric analyses](../orbits/README.md) determine original energy at 250 au for selected objects, test planetary encounters, model cometary acceleration, and examine observation or station holdouts.

## Astrometry, fit and reporting epoch

[refit.py](refit.py) reads the archived MPC comet-observation file to the end, checks packed identifiers, preserves observation strings in input order, and excludes records mapping to multiple JPL identifiers. The receipt gives the bulk source, server timestamp, SHA-256, number of lines and number of object matches. Each fit records a SHA-256 for its own input bytes. Duplicate fragments, alternate designations, spacecraft continuation lines, and the coverage of the MPC comet file limit the mapping. The separate [current MPC requests](latest.py) use full comet designations and asteroid aliases for recent updates, asteroid-class records and recent short-arc comparison objects. Each live response records its request, timestamp, hash and match status.

[build.sh](build.sh) builds pinned Find_Orb, lunar, sat_code and jpl_eph revisions and retrieves the JPL DE430t file. Run it with an empty temporary build directory. The fitter reads the actual MPC records for each object in an isolated output directory, with planetary perturbations and an explicit barycentric report command (`-h-1`). The target epoch is 300 Julian years before the catalogue perihelion, clipped at the inner edge of the available time range. The short-arc comparison instead uses the last observation as an anchor where its saved table omits perihelion time. The requested date is an output epoch. [Find_Orb command reference](https://projectpluto.com/fo_usage.htm)

The [joined table generator](../summarize.py) checks the returned center, epoch, radial motion and barycentric radius. Only incoming solutions at least 100 au out and at the requested epoch populate its far-inbound columns. The radius and sign of radial motion are reconstructed from the returned conic with the system gravitational parameter. For elliptic solutions we take mean anomaly modulo a full revolution. This fixed-epoch test can sample another revolution or fail to reach the distance gate. It does not locate the first 250 au inbound crossing. An absent estimate therefore leaves the origin unresolved.

The fitter records how many observations it used and its residual RMS. The formal excess in the joined table uses `(e−1)/sigma_e` from one local model. A covariance estimate, a small residual and a negative reciprocal semimajor axis cannot by themselves resolve short-arc orbit alternatives, nongravitational acceleration, historical systematics, spacecraft astrometry or fragment identity. The batch limits each attempt to 18/20 seconds of CPU soft/hard limits and 27 seconds wall time. Timeouts remain explicit dispositions.

## Replay

From this directory, run `bash build.sh /path/to/empty/build` then `python refit.py`. Run `python latest.py` for the live API refresh. The live files are mutable. Match the response hashes before comparing outputs. `neocp_history.py` additionally requires Beautiful Soup and examines published astrometry of unconfirmed departures in the specified time window.

From the parent directory, `python summarize.py batch/evidence` regenerates the joined disposition and counts from the checked-in evidence. The [catalogue audit](../catalog/README.md) regenerates the JPL osculating two-body quantities directly from the frozen JSON. The published CODE comparison and the two independent fit implementations are recorded separately.
