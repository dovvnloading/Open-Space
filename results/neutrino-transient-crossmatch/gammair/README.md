# Mid-infrared and gamma-ray inputs

## Mid-infrared

The primary MIR table contains all 823 dust-echo-like flares in Necker et al., including the corrected CDS catalogue dated 2026-06-30. The reference UTC epoch derives from the authors' observer-frame mean peak time (`RefTime`, MJD). The observed peak range runs from 2010-07-04 to 2022-06-17. This catalogue has no flare with a 2024 peak. It cannot measure the all-sky incidence of flares in 2024–2026. [Article](https://doi.org/10.1051/0004-6361/202451340) · [Erratum](https://doi.org/10.1051/0004-6361/202661646e) · [CDS release](https://cdsarc.cds.unistra.fr/viz-bin/cat/J/A+A/695/A228)

The supplementary 2MRS table contains 108 independently selected hosts with `vetted=True` after excluding five classified off-nuclear flares. These include active nuclei and candidates with weak or multiple peaks. The original catalogue classified each source. Seventeen peak visits fall in 2024. The unique W2 visit within one day of each reported rounded-year peak supplies its UTC epoch. Five hosts fall within five arcseconds of a Flaires entry and are identified for deduplication before any combined analysis. This repository sample has a nearby-galaxy selection function. The main experiment can use the published catalogue alone and report the supplementary sample separately. WISE observations ended in 2024. [Pinned repository survey](https://github.com/dovvnloading/Open-Space/tree/7d266947bd5c64e945ab040173b5ffb660c38ca3/results/neowise-nuclear-flares) · [IRSA final release](https://irsa.ipac.caltech.edu/data/WISE/docs/release/NEOWISE/)

`flaires_raw.tsv.gz` retains the full VizieR response, including its service timestamp, schema, units and release date. `mir_receipts.json` includes SHA-256 for its decompressed bytes and both pinned 2MRS repository inputs. Run `python freeze_mir.py /path/to/Open-Space` from this directory to replay, or use `--download` to fetch the live VizieR catalogue. A fresh query includes a fresh service timestamp.

## Gamma rays

The NASA Fermi-LAT LCR API supplied the catalogue and weekly fixed-index likelihood fits. In the DR2 source list, select variability index >21.67 and CLASS1 (case-insensitive) in FSRQ, BLL and BCU, including blazar candidates of uncertain type. The LCR was built for the variable DR2 population, so it omits blazars outside this selection and new sources discovered after DR2. It measures 0.1–100 GeV photon flux averaged over a week. [Repository](https://fermi.gsfc.nasa.gov/ssc/data/access/lat/LightCurveRepository/about.html) · [NASA schema and MINUIT flags](https://fermi.gsfc.nasa.gov/ssc/data/access/lat/LightCurveRepository/table_description.html)

`fetch_lcr.py CACHE` fetches the parent list and per-source responses with receipts. `python freeze_lcr.py --cache CACHE` verifies the source-response hashes and saves the effective inputs and per-source denominators. A bin must end before the cutoff. The code joins all arrays by bin-center MET, uses the symmetric Gaussian-equivalent error (half the distance between published low and high bounds), and implements the preregistered TS, convergence, S/N and flare cuts. An unavailable week separates two episodes. Each peak is the midpoint of the highest-flux selected week, with ties assigned to the earlier week. The fixed seven-day bins limit timing precision. UTC times subtract leap seconds accumulated since 2001-01-01.

`weekly_inputs/` retains all bins meeting the preregistered quality cuts, prior to any threshold relative to a source's median. These compressed tables reproduce the median, episode boundaries and peak data without requerying NASA. `lcr_source_counts.csv` records all returned TS bins before cutoff, quality survivors and coverage per source, including zero survivors. `lcr_receipts.csv` records the raw HTTP payload SHA-256 for every source and the complete DR2 list. The live API changes with later observations. Low-quality and upper-limit fits can be re-requested using the recorded URLs and checked against those hashes. Run `python freeze_lcr.py` to reproduce all peaks offline.
